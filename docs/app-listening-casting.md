# App 收听、服务商设置与演员表

App 的界面由 Claude 实现。`lib/application/contracts.dart` 定义页面使用的播放、配置、同意与演员表接口；`AppServices` 在启动时将真实实现接入页面。界面测试使用这些接口的假实现。

## 收听

从书架或章节打开收听时，`ListeningController` 优先读取有效的已合成音频，其他章节使用手机的系统语音。系统语音按中文或英文选择本地音色，按句生成本地 WAV，再交给同一个音频引擎播放。长句分块保留原文的 UTF-16 区间与完整文字。生成的本地语音缓存在书的音频目录内，删除书时一并清理。

已合成音频沿用台词与停顿共用的 PCM 时间轴，按剧本、音色和发音词典的输入哈希缓存连续播放文件。正文高亮跟随当前台词；点台词打开操作菜单，选择「从这里播放」后才改变播放位置。

播放器支持播放、暂停、前后句、前后章、0.5–3 倍速、按时长关闭与播完本章关闭。章节播放完成后继续下一章，每本书保存章节、台词和全书进度。系统语音的章节进度按句计算，完整章节时长在逐句合成期间尚未确定。音频中断或耳机断开时暂停。

`ListeningHandler` 将通知栏和锁屏命令交给同一个控制器：跳过对应前后句，快进/快退对应前后章，队列索引对应章节。实际系统界面提供的按钮由系统决定。

## 服务商与发送同意

LLM 设置包含 base URL、Chat Completions 或 Responses 协议，以及建档、导演两个模型槽位。导演模型留空时使用建档模型。MiniMax 和百炼各保存独立 key，百炼可选择北京或新加坡区域。

key 保存在 iOS Keychain 和 Android Keystore 支持的安全存储中。普通 SQLite 设置保存地址、协议、模型和区域；页面读取已保存 key 的存在状态。保存时，空缺参数保留 key，空字符串删除 key，其他字符串替换 key。App 通过内存配置快照创建适配器。

每次操作在发送内容前核对目标服务商和实际地址的同意记录。请求同意时展示书名、接收方、地址和内容类型；取消后操作结束。LLM 地址或百炼区域改变后，相应的新目的地重新请求同意。服务商接受的请求沿用 core 的本地用量记录，保存于 App 私有目录的 `usage.jsonl`。

## 建档与演员表

建档由持久化 `Scheduler` 执行，范围按章节选择并可向后延伸。任务按章保存，中断后继续未完成的章节。key、余额或网络问题会暂停任务，并以可本地化的固定错误类别交给界面；更新设置后可以继续。

建档后自动推荐选角，延伸时保留已有音色并补齐新增角色。全局专属音色数量默认 20，修改后重新推荐。演员表提供旁白、角色、身份和临时角色；页面接口只暴露各自的资料，身份与所属角色的关联保留在 core 内。

试听样音保存在书的音频目录内，再次试听复用已保存文件。停止尚未完成的试听会保留生成结果并取消自动播放。正式收听和角色试听共用互斥播放行为。

## 开发验证

```sh
dart test packages/core/test
cd packages/app
flutter test
flutter test integration_test/native_services_test.dart -d <device>
flutter test integration_test/library_test.dart -d <device>
```

业务测试使用假 LLM、假 TTS、假播放引擎和临时数据库。原生服务测试在设备上验证安全存储、系统语音、句章控制、倍速和播完停止，使用系统本地语音。iOS 构建通过 CocoaPods 集成 `flutter_tts`。

人工锁屏操作及听感记录继续归入 [#56](https://github.com/dayeguilaiye/pagestage/issues/56)。

2026-10-25，core 的 228 项测试和 App 的 78 项测试通过，完整静态分析通过。iOS 与 Android 模拟器均通过原生服务测试及书库集成测试，覆盖本地系统语音、安全存储、倍速、句章控制、播完停止、GBK 导入、设置恢复和删除。书籍建档及 TTS 服务商行为使用离线适配器验证。
