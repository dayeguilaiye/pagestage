# CLI 导演

先用 `profile` 建档到目标章节，再导演：

```sh
dart run packages/core/bin/pagestage.dart direct <book-id> 1 \
  --chunk-characters 6000 --config .pagestage/providers.json
```

导演使用 [LLM 配置](cli-profiling.md) 的 `directorModel` 槽位，默认沿用建档模型。输出包含剧本、每条台词的原文和说话人、耗时、token 用量、请求次数、分块数，以及模型和提示词版本。剧本与新临时角色在整章完成后一起写入 SQLite，服务商报错时保留先前已保存的结果。

每条台词记录原文中的 UTF-16 闭开区间 `[start,end)`。原文以导入后的 `Chapter.text` 为准；剧本保存正文 SHA-256，读取剧本的模块应与当前章节哈希比对。台词区间按顺序完整覆盖章节正文。朗读文本始终从原文区间取得，LLM 返回的文本只用于定位。

对齐容许标点、空白和常见全角/半角形式的差异。若有漏读原文或无法定位的台词，本块最多再导演两次。最终剧本保留能够对齐的台词，把遗漏的原文交给旁白，并舍弃无法定位的模型台词。空白章节直接保存为旁白区间。

`--chunk-characters` 是每块的 Unicode 字符目标值，默认 6000；分块保持自然段完整，单个长段落可以超过目标值。每块携带前一块末尾三条已对齐台词；章节首块使用上一章已经保存且正文哈希一致的剧本末尾三条台词。上下文中的台词只用于衔接。

导演看到的演员表仅包含截至本章已知的说话人标识、名字和别名。身份在揭晓前独立出现；揭晓后可以使用所属角色。未知说话人会形成稳定的临时角色，留给下次延伸建档处理。提示词区分第三人称旁白、实际第一人称“我”、书信/日记作者和系统提示，并要求克制的情绪表演；带动作的叙述保持正文，纯说话提示及非正文分别记录标记。

离线测试使用假 LLM 验证原文覆盖、标点和全角容差、重试与兜底、长章衔接、身份隔离、临时角色和事务保存。真实模型对两本测试书第一章的说话人质量验收仍待 key 配置完成，对应待验项记录在 GitHub issue #8。
